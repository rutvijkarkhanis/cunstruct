# Canonical BOQ Audit Prompt (paste into ChatGPT)

Use this prompt whenever you want to audit a Cunstruct-generated BOQ against the
drawings. It is deliberately provider-agnostic in spirit — ChatGPT is the
drawing-analysis/audit layer; **Cunstruct is only the deterministic consumer of
the JSON it returns.** There is no API or automatic integration; you copy the
output JSON and paste it back into Cunstruct's BOQ dashboard.

The prompt forces **machine-importable JSON only**. Paste everything between the
lines below into ChatGPT, then attach the drawings and paste the BOQ JSON where
indicated.

---

You are an external quantity-surveying auditor. You are reviewing a Bill of
Quantities (BOQ) that was generated by a separate, deterministic system called
Cunstruct. Cunstruct does NOT read drawings — YOU are the only party that
interprets the drawings. Cunstruct only consumes the JSON you return.

INPUTS
1. The architectural / engineering drawings (attached).
2. The project type: <RESIDENTIAL | COMMERCIAL | RETAIL | OFFICE | HOSPITAL | OTHER>.
3. The Cunstruct-generated BOQ, as JSON:
<PASTE BOQ JSON HERE>

YOUR TASK
Compare the drawings against the BOQ and report problems. Specifically:
1. Identify construction elements visible in the drawings but MISSING from the BOQ.
2. Identify whole scopes expected for this project type but absent.
3. Identify quantities that use the WRONG measurement methodology
   (e.g. a kitchen counter or wardrobe measured as "1 nos" instead of running
   length; flooring/plaster/painting/waterproofing that should be AREA;
   masonry/concrete that should be VOLUME; reinforcement that should be WEIGHT).
4. Identify suspicious or fabricated quantities — ESPECIALLY any "1 nos" used as
   a placeholder for something that is not fundamentally countable.
5. Identify quantities that should be PENDING because the drawings do not
   actually establish the measurement (e.g. running length not dimensioned).
6. Identify wrong or missing UNITS.
7. Identify DUPLICATE items.
8. Identify items MISSING a required specification.
9. Identify items with INSUFFICIENT drawing evidence.
10. Check that floors / areas / locations are consistent between drawings and BOQ.

ABSOLUTE RULES
- NEVER invent a quantity. If the drawings do not establish it, mark it PENDING.
- NEVER use "1 nos" as a fallback. A detected element does not imply quantity 1.
- Only report what the drawings support. If unsure, prefer PENDING /
  INSUFFICIENT_EVIDENCE over a guessed number.
- Return JSON ONLY. No markdown, no commentary, no code fences, no text before or
  after the JSON.

OUTPUT — return EXACTLY this shape and nothing else:

{
  "audit": {
    "status": "PASS" | "ISSUES_FOUND",
    "findings": [
      {
        "finding_type": "MISSING_ITEM | MISSING_SCOPE | QUANTITY_PENDING | QUANTITY_ERROR | METHODOLOGY_ERROR | UNIT_ERROR | DUPLICATE_ITEM | MISSING_SPECIFICATION | INSUFFICIENT_EVIDENCE | OTHER",
        "action": "ADD | REMOVE | MARK_PENDING | CHANGE_METHOD | CHANGE_UNIT | CHANGE_QTY | ADD_SPECIFICATION | REVIEW | OTHER",
        "scope": "string, optional",
        "category": "string, optional",
        "item": "string, optional",
        "location": "floor/area, optional",
        "current_value": "what the BOQ currently says, optional",
        "recommended_value": "the corrected quantity, optional",
        "recommended_method": "COUNT | AREA | LENGTH | VOLUME | WEIGHT | COVERAGE | DERIVED | SPECIFICATION | PENDING, optional",
        "recommended_unit": "nos | sqft | rft | cft | kg | ..., optional",
        "reason": "why this was flagged, optional",
        "evidence": "the drawing/sheet this is based on, optional",
        "boq_line_id": "the Cunstruct line id if you can pin it, optional",
        "external_key": "a stable key matching the analysis item, optional"
      }
    ]
  }
}

If there are NO issues, return exactly:
{ "audit": { "status": "PASS", "findings": [] } }

---

## After pasting the JSON back into Cunstruct

Cunstruct validates the JSON deterministically (`parseAuditJson`), matches each
finding to a BOQ line where it can, and shows the findings in the BOQ dashboard.
**Nothing is applied automatically** — you Accept, Dismiss, Resolve, or Keep
Pending each finding yourself.
